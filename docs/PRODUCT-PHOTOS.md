# Product photos

Each knowledge item in AI Knowledge or Sources accepts up to **7** JPG, PNG, or WebP photos, **5 MB each**. Save a new knowledge item before adding photos. A visible upload counter reports progress and partial failures. Duplicate image bytes reuse the existing photo instead of using another slot.

The authenticated API decodes every upload, rejects corrupt/animated/oversized images and images over 40 megapixels, strips metadata, and stores an oriented JPEG at a maximum of 2048 × 2048 without cropping. Transparent images receive a white background. Objects stay in the private generated-assets bucket with short-lived preview URLs. Server preview URLs are cached for 50 minutes (500-entry bound) so refreshes reuse browser image caches.

In Create, select approved knowledge. **AI visual from product photo** is the default. The Worker finds up to seven eligible photos, ordered by photo slot then most recently updated knowledge (one first photo per source before extra slots). OpenRouter vision selects the photo that best fits the brief and describes visible features. You can select one photo yourself to override that choice. The copywriter receives the same visual description and must cite its approved knowledge source. Factual claims still come from approved text, never inferred prices or benefits.

OpenRouter Images receives the actual private reference image and the draft's matching visual brief. Platform posters use FLUX.2 Klein with separate layouts and dimensions for Instagram, TikTok and X, including text-only poster generation. Legacy direct image calls without poster dimensions retain the configured text-to-image model. See POSTER-GENERATION.md. **Use original photo unchanged** attaches the chosen original without an OpenRouter image call; **Create without product photos** opts out. Disabling visuals still allows photo-grounded copy. Provider failures are explicit; no unrelated text-only fallback occurs.

Review includes the original reference thumbnail. AI edits can alter details and lettering: compare the result before approving it. Regeneration retains the same original reference, even if the photo was unlinked from the library; archived knowledge or assets block its use. Existing approval and Buffer submission/reconciliation remain unchanged.

Remove photo unlinks it from the knowledge library and frees a slot. Existing drafts retain their assets. Uploads do not alter approved textual facts. The API and Worker verify workspace ownership, source approval, and photo membership; removal before generation completes prevents stale attachment.
