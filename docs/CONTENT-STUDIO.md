# Guided content studio

## News discovery

News / topic workspaces can search recent Google News reporting through the server-side SerpAPI provider. A selected result becomes a draft source with its original URL and must be approved before it can guide generation. `SERPAPI_API_KEY` is optional and never sent to the browser.

The local homepage now opens on **Create**. The supplied logo anchors the navy, mint, and violet design. Existing workspace, content library, sources, inbox, activity, and settings remain accessible in the sidebar.

1. **Your idea:** choose one or more approved items in **Choose knowledge for this post** (search covers both AI Knowledge and Sources). Add an optional brief, select English or Arabic, choose Instagram/TikTok/X, and optionally enable images. **Create post** on an AI Knowledge card opens Create with that item selected. Draft items must be approved first. Only selected items are sent to OpenRouter; unrelated library entries are excluded. Existing API clients that omit `knowledgeIds` keep using approved content sources only. The API validates ownership and approval, and the worker checks again before generation and saving. The source IDs remain attached to each draft. No database migration or new credential is required.
2. **Generate:** OpenRouter receives a strict JSON schema with the required fields and approved source IDs, routed only to providers supporting the request parameters. Every response is still validated locally for platform completeness, source membership, and length. Invalid or truncated content gets one automatic repair attempt; refusals and HTTP failures are not retried this way. Each request has a 60-second timeout. Nothing is persisted until the whole batch validates. When requested, the worker inserts each draft and its OpenRouter Gemini image job in the same database transaction. The generation result references its draft and image-job IDs. The browser polls job status; closing the page does not cancel server work.
3. **Review:** inspect captions, scripts, and generated images; edit captions or request a new image. Unsaved caption edits must be saved before sharing. Failed image work is shown explicitly and can be retried. FLUX base64 responses are decoded before storage in the private Supabase bucket.
4. **Share:** select eligible connected channels and choose **Publish now** or **Schedule**. Scheduled times must be at least one minute ahead and within seven days. Final approval creates durable submission jobs. Buffer submission and confirmed publication are shown separately. Edits revoke previous approvals; a submission with an uncertain outcome is held for reconciliation to prevent duplicates.

Instagram and TikTok support photo posts through Buffer and require an image. X supports text with an optional image. TikTok generation produces a photo caption; video creation is not implemented. Instagram submissions include the required post metadata. Private images receive time-limited delivery URLs for Buffer.

Social accounts has persistent Instagram, TikTok, and X panels with immediate views of posts published through Nabd, connection status, supported formats, and publishing activity. The first three saved post images per account preload in the background. TikTok’s public creator preview stays mounted when switching accounts or app sections. Instagram/X no longer rely on blank public embeds. Open full account opens the real profile in a separate browser tab; full signed-in experiences cannot be embedded or inherit another browser’s cookies. Using Nabd in Chrome lets profile links use Chrome’s own session. These saved views do not claim to include posts made outside Nabd or live follower counts. “Active” means a connected channel verified within the past 24 hours, not live user presence. Connection metadata distinguishes Buffer publishing from Unipile messaging. Refresh checks run through the existing durable worker.

The September 20 workspace cleanup archives previous drafts, completed activity, generated assets, and the test conversation. Reconciliation continues for previously submitted posts even when their local history is archived.

All privileged writes still go through the API. Frontend code uses no server credentials. The no-login mode remains limited to the existing local development access rules. Email remains deferred; n8n is not part of content generation or publishing.
